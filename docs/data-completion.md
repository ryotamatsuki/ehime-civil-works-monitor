# Phase 2.3 Data Completion

Phase 2.3 deepens the 50-project Phase 2.2 inventory without increasing project count. The priority is to move Inventory-only records into Snapshot / History / Enriched only when project-specific primary sources support the values.

## Result

Phase 2.2 baseline:

- Projects: 50
- Inventory: 17
- Monitored: 33
- Enriched: 22

Phase 2.3 after source completion:

- Projects: 50
- Inventory: 4
- Snapshot: 18
- History: 0
- Enriched: 28
- Monitored: 46
- History+: 28

`History = 0` is an exclusive Data Depth result. Historical observations exist; projects with deeper Phase 2.1 data are classified as `Enriched`.

## Four records intentionally left at Inventory depth

### 沢津地区 急傾斜地崩壊対策事業

Official procurement information identifies individual work packages, but an authoritative current total project cost / completion target / comparable project progress value was not confirmed. A contract amount is not used as total project cost.

### 松山港 港湾改修事業

The broad map label overlaps multiple port districts and individual terminal/port-improvement projects. A district-specific value is not aggregated into the broad canonical record without a source defining the same scope.

### 一般県道 嵐田之浜岩松線 翼橋

Official documents confirm the project/work, but a sufficiently clear current whole-project cost or completion snapshot was not confirmed. Individual annual allocation or work-package amounts are not substituted.

### 北山崎海岸 高潮対策事業

Older official material exists, but a current project-specific completion target and comparable snapshot were not verified strongly enough for a 2026 current value. A stale completion estimate is therefore not promoted to the current snapshot.

## Data-completion rules

1. A value is promoted only when the source scope matches the canonical project.
2. A fiscal-year plan period is not automatically interpreted as the original project adoption year.
3. A past completion estimate that has already elapsed is not used as a current completion target unless a current source confirms it.
4. Section-level construction-start rates are not converted into physical progress percentages.
5. Approximate expressions such as `約62億円` may be normalized into million yen only with an explicit note preserving the source semantics.
6. A single current observation may create Snapshot data, but cannot create a Change Event.
7. Cost / Schedule / Progress changes remain derived only from comparable consecutive history observations.
8. Documented Reasons record what an official source says; they do not create a COST+ / DELAYED event when the comparable prior value is missing.
9. Annual allocations, contracts and cumulative investment remain separate from total project cost.
10. Unknown values remain `null` / empty history rather than being inferred.
